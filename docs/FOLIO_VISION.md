# Folio Vision

**Document ID:** FOLIO-PRODUCT-002  
**Status:** Agreed product direction  
**Product:** FOLIO Studio  
**Positioning:** The Unified Creative Development Studio

## Vision statement

**FOLIO Studio is a unified, visual-first creative development environment where people can design, code, animate, edit video, and turn ambitious digital ideas into finished digital products within one coherent project—even when their facilities are limited—without taking freedom away from developers.**

## The future FOLIO is working toward

FOLIO aims to become an all-in-one creative development studio: one environment for the connected journey from visual idea to engineered product and finished media. It brings specialist workflows together without turning them into disconnected applications or forcing every discipline into one oversized engine.

The ambition is still often described as **FL Studio for Web Development**: a creative, multi-panel and timeline-oriented workspace in which visual creation and technical production can happen together. The metaphor describes the expressive workstation experience; it does not limit FOLIO to web design or require it to copy another product.

FOLIO's long-term creative disciplines include:

1. **Design and vector creation.** Compose interfaces, illustrations, shapes, typography, layouts, design systems, and reusable components.
2. **Code and full-stack development.** Work directly with source code, application structure, logic, backend integrations, runtime, and deployment.
3. **Motion and animation.** Animate objects and interfaces through timelines, keyframes, easing, interactions, and advanced geometry morphing.
4. **Video and media editing.** Build non-destructive media timelines with video, audio, clips, transitions, effects, and compositing as the dedicated media workflow matures.
5. **Interactive behavior.** Connect visual objects and applications to events, state, data, and runtime behavior through Node Logic and code.

These disciplines should feel like focused workspaces within one studio. A user should be able to move from a vector object to an animation, from an animation to a website, and from project output to a promotional video without rebuilding the same assets or losing their relationships.

## The principles behind an all-in-one studio

1. **One project, many disciplines.** Design, code, Node Logic, motion, media, assets, and application output share one coherent project identity and explicit relationships.
2. **Specialist tools, shared project truth.** Each discipline may have its own engine, editor, timeline, and interaction model. They must operate through the Unified Project Model and native contracts rather than create competing project silos.
3. **Non-destructive interoperability.** Moving between workspaces should preserve source assets and editable relationships wherever supported. Exported or rendered output must not silently replace the original project content.
4. **Creative power without developer lock-in.** Visual workflows should accelerate creation while developers retain direct access to code, structure, logic, and implementation details.
5. **Extensible engines, not a monolith.** FOLIO should add specialized capabilities through modular engines and stable contracts. A video editor, for example, should not compromise the geometry or code engines.
6. **Resource-aware ambition.** Progressive loading, efficient data structures, proxies, caching, and capability-aware rendering should make advanced workflows as accessible as practical on modest hardware.
7. **Portable and durable projects.** The native .flop format should evolve through explicit versioning and migrations while preserving supported assets, identities, and relationships.
8. **Project-aware AI and collaboration.** Future assistance and collaboration should understand the real project model and use authorized native operations.

## What success should feel like

- A creator can design an identity, animate it, use it in a website, and produce media around that website without recreating the work in unrelated applications.
- A designer can create visually without first translating every thought into code.
- A developer can inspect, edit, and own the real implementation rather than surrendering control to a visual abstraction.
- An animator can make one object change shape while preserving its identity, rather than faking the transition with unrelated objects.
- A video editor can work non-destructively with project assets and media tracks while keeping the original source material safe.
- Moving between workspaces feels like changing tools inside one studio, not switching to unrelated products.
- The project can grow from a small idea into a complex interactive product and its supporting media without losing structural integrity.
- Advanced capabilities remain modular and progressively available instead of making the entire studio heavy for every user.

## Scope and honesty

This vision describes the long-term product destination, not a claim that every discipline is already implemented. The repository currently contains meaningful foundations for visual design, code workflows, Node Logic, motion animation, and motion export. A full non-destructive multitrack video-editing workspace and native geometry Morph animation remain roadmap capabilities.

Each capability must be classified in the architecture and roadmap as agreed, proposed, open, implemented, or verified. A feature is not complete because it appears in this document. See [FOLIO Creative Studio Direction](FOLIO_CREATIVE_STUDIO_DIRECTION.md) for the discipline boundaries, interoperability principles, and staged direction.
