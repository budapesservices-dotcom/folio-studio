# Folio Mission

**Document ID:** FOLIO-PRODUCT-003  
**Status:** Agreed product direction  
**Product:** Folio

## Mission statement

**Folio empowers designers and developers to create sophisticated digital products together by connecting visual expression and direct engineering work through an efficient, extensible, and dependable native project environment.**

## How Folio pursues its mission

### 1. Make creation more accessible

Prioritize efficient architecture, lightweight defaults, progressive capabilities, and workflows that avoid unnecessary resource consumption. Hardware limitations should be treated as an engineering challenge, not as a reason to exclude creators.

### 2. Give visual creators a capable workspace

Build a professional visual environment for composing, arranging, editing, and understanding digital interfaces. The workspace should support focused tools and multiple views while keeping the project model independent from the UI.

### 3. Preserve developer freedom

Allow developers to work directly with source code and implementation logic. Make visual-to-code relationships transparent, preserve custom and unmapped work, and never claim arbitrary code is fully visually editable.

### 4. Connect work through one native project model

Use one Unified Project Model, stable identities, typed contracts, validated commands, and explicit synchronization. Designer, Developer, Node Logic, and future workspaces are independent experiences over shared project truth.

### 5. Build native foundations before accumulating features

Own the project contracts, commands, identity, AST, synchronization rules, and compiler orchestration. Reuse mature external libraries when useful, but do not delegate Folio's project truth to them.

### 6. Make projects durable and portable

Maintain the .flop format with explicit format identity, versioning, compatibility rules, and migrations. Saving, opening, importing, exporting, or upgrading must not silently discard supported project data.

### 7. Make AI a context-aware collaborator

Give AI agents the product purpose, architecture, current implementation reality, task boundaries, and acceptance criteria before they change the repository. AI must extend the existing system rather than inventing a competing source of truth.

### 8. Advance through verifiable increments

Prefer modular changes, explicit acceptance criteria, regression tests, measured performance, and honest status reporting. Do not represent a planned capability as implemented or an implementation as verified without evidence.

## Mission guardrails

- Folio supports professionals and learners; it is not a substitute for their judgment or craft.
- Visual convenience must not override data integrity or developer control.
- Reuse is encouraged, but native project contracts remain authoritative.
- Accessibility and low-resource design must be pursued through measurable engineering choices.
- Product growth must remain aligned with the manifesto and vision.
