# Folio Mission

**Document ID:** FOLIO-PRODUCT-003  
**Status:** Agreed product direction  
**Product:** FOLIO Studio

## Mission statement

**FOLIO empowers designers, developers, and digital creators to design, build, animate, and produce digital experiences together through one efficient, extensible, and dependable native project environment.**

## How FOLIO pursues its mission

### 1. Make ambitious creation more accessible

Prioritize efficient architecture, lightweight defaults, progressive capabilities, and workflows that avoid unnecessary resource consumption. Hardware limitations should be treated as an engineering challenge, not as a reason to exclude creators. Performance must be measured on realistic target devices.

### 2. Give visual creators a powerful workspace

Build professional tools for composition, vector geometry, typography, layout, reusable components, and visual systems. Make complex operations discoverable and direct without hiding the underlying structure from advanced users.

### 3. Preserve developer freedom

Allow developers to work directly with source code, application structure, and implementation logic. Make visual-to-code relationships transparent, preserve custom and unmapped work, and never claim arbitrary code is fully visually editable.

### 4. Make motion a first-class creative discipline

Connect animation timelines, keyframes, easing, playback, object identity, interactions, and runtime behavior to the same project. Pursue advanced capabilities such as geometry Morph so a single object can change shape while retaining its identity. These capabilities must be designed and verified incrementally.

### 5. Bring video and media production into the studio

Build toward a dedicated, non-destructive video and media workflow for arranging video and audio clips, tracks, transitions, effects, and compositing. Reuse project assets and shared identity where appropriate, while preserving a specialized media engine and timeline model. Existing motion export must not be confused with a complete video editor.

### 6. Connect every discipline through one native project model

Use one Unified Project Model, stable identities, typed contracts, validated commands, and explicit synchronization. Design, Developer, Node Logic, Motion, Media, and future workspaces are independent experiences over shared project truth—not separate databases.

### 7. Build native foundations before accumulating features

Own the project contracts, commands, identity, AST, synchronization rules, asset references, and compiler orchestration. Reuse mature external libraries when useful, but do not delegate FOLIO's project truth to them. Specialized engines should remain modular and have clear ownership boundaries.

### 8. Make projects durable and portable

Maintain the .flop format with explicit format identity, versioning, compatibility rules, and migrations. Saving, opening, importing, exporting, or upgrading must not silently discard supported project data, media references, or editable relationships.

### 9. Make AI a context-aware collaborator

Give AI agents the product purpose, architecture, current implementation reality, task boundaries, and acceptance criteria before they change the repository. AI must extend the existing system rather than inventing a competing source of truth.

### 10. Advance through verifiable increments

Prefer modular changes, explicit acceptance criteria, regression tests, measured performance, and honest status reporting. Do not represent a planned capability as implemented or an implementation as verified without evidence.

## Mission guardrails

- FOLIO supports professionals, learners, and independent creators; it is not a substitute for their judgment or craft.
- All-in-one means integrated workflows and shared project truth, not one monolithic engine or an uncontrolled list of features.
- Visual convenience must not override data integrity or developer control.
- Reuse is encouraged, but native project contracts remain authoritative.
- Video and other media workflows must be non-destructive and must not silently overwrite original source assets.
- Accessibility and low-resource design must be pursued through measurable engineering choices.
- Product growth must remain aligned with the manifesto and vision.
